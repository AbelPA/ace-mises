## Summary

First functional implementation of the Agent-Based Computational Economy (ACE), inspired
by Ludwig von Mises's theory of human action (praxeology). v0.1 is **minimal**,
**deterministic**, and **domain-oriented**: agents with basic food needs, some producers,
physical inventory, identification of unfulfilled needs, voluntary bilateral barter
exchanges, consumption at the end of each period, and binary survival/death.

It is the **minimum acceptance criterion** of v0.1: the A/B scenario (two producers with
reciprocal needs and complementary surpluses), validated by 20 automated tests that all
pass.

## Added

### Domain (`ace.domain`)

Implemented the complete minimal domain, organized in 3 subnamespaces:

- **`ace.domain.economy`**
  - `FoodType` (enum): `Wheat`, `Corn`, `Meat`, `Milk` — the only economic goods in v0.1.
  - `Need` (sealed record): minimum survival quantity per period; invariant
    `QuantityPerPeriod > 0`.
  - `Production` (sealed record): deterministic productive capacity per period; invariant
    `QuantityPerPeriod > 0`.
  - `Inventory` (sealed class): physical stock per `FoodType`; `Get`, `Has`, `Add`,
    `Remove` with validation of quantity > 0.

- **`ace.domain.agents`**
  - `AgentType` (enum): `Producer`, `Consumer`. Every Producer is also a consumer.
  - `Agent` (sealed class): main entity with `Id`, `Name`, `Type`, `Inventory`, `Needs`
    (`ImmutableArray<Need>`), `Productions` (`ImmutableArray<Production>`), and
    `IsAlive` (binary survival). Behaviors:
    - `Produce()` — produces everything alive; adds to the inventory; does not remove
      resources.
    - `UnfulfilledNeeds()` — returns needs not satisfied by the inventory.
    - `NeedsFood()` — `true` if there is any unfulfilled need.
    - `Consume()` — two-pass binary survival: if any need is unfulfillable, the agent
      dies and consumes nothing; otherwise removes all needs and remains alive.

- **`ace.domain.exchange`**
  - `Offer` (sealed record): barter proposal (`Seller`, `OfferedFood`, `OfferedQuantity`,
    `RequestedFood`, `RequestedQuantity`). No monetary price.
  - `Exchange` (sealed class): bilateral and atomic transfer via `Execute()`; validates
    both inventories before any mutation — if it fails, returns `false` and does not alter
    any inventory.

### Application (`ace.application`)

New project that orchestrates the economic cycle per period.

- `EconomicCycle.RunPeriod(IReadOnlyList<Agent> agents)` — runs the mandatory cycle:
  **Production → Needs → Trades → Consumption → Survival**.
- `DiscoverAndExecuteTrades` (private) — O(n²) pairwise discovery under the complete-
  information assumption of v0.1; criterion: A needs X + B has X + B needs Y + A has Y →
  atomic bidirectional `Exchange.Execute()`. Deterministic iteration in list order; one
  exchange per pair per period.
- `Simulation` — convenience wrapper to execute N periods.

### Tests (`ace.tests`)

New project with xUnit; **20 tests, all green**.

- `AbScenarioTests` — the mandatory A/B scenario (spec 004 / EXP-001): two producers
  with reciprocal needs (A produces Wheat/needs Meat; B produces Meat/needs Wheat);
  validates exact inventories at each step and `IsAlive == true` at the end.
- `DomainUnitTests` — 19 tests covering specs 001-004:
  - Inventory (5): `Add`/`Get`/`Has`/`Remove` and invalid quantity rejection.
  - Production (4): live producer produces, multiple productions accumulate, repeated
    periods accumulate, dead agent does not produce.
  - Exchange (3): valid exchange transfers bidirectionally, failure by lack on either
    side does not alter inventories.
  - Survival (5): `UnfulfilledNeeds`/`NeedsFood` and `Consume` (satisfied, fatal, and
    dead-agent no-op).

- `ace-mises.sln` — references 3 projects (`ace.domain`, `ace.application`, `ace.tests`).
- `.gitignore` — added `bin/` alongside `obj/`.

## Compliance with the governing constitution

v0.1 respects all principles and prohibitions defined in
[`specs/constitution.md`](../../specs/constitution.md):

- **Minimal domain, domain-oriented** — only the explicit concepts (`Agent`,
  `AgentType`, `FoodType`, `Inventory`, `Need`, `Production`, `Offer`, `Exchange`) exist.
  No invented concepts.
- **Clean Architecture** — dependencies point inward (`ace.domain ← ace.application ←
  ace.infrastructure ← ace.console`); the domain does not know the simulation.
- **Determinism** — deterministic production, no uncertainty, no variable productivity.
- **Voluntary bilateral exchange** — the only economic transfer between agents is
  `Exchange`; atomic, bilateral, and voluntary. No `Give`/`Transfer`/`Donate`/`Steal`.
- **Binary survival** — `IsAlive` is only `Alive`/`Dead`; no health, age, hunger,
  damage, recovery, or reproduction.
- **Incremental evolution** — no concept introduced from the formal prohibitions list
  (Money, Price, Currency, Utility, Market, Capital, Labor, Tax, Government,
  Technology, Expectation, Preference, Profit, Loss, etc.).
- **No `Market`** — either in the domain or in the application; the discovery of
  opportunities is performed by the application without being a centralized market object.

## Out of scope (deliberately)

The following items are **not** part of v0.1 and were not implemented:

- Spec [`005-limited-information`](../../specs/005-limited-information/spec.md) —
  prospective (v0.2+), agents with partial information and exploration/exposal of offers.
- Application layers `ace.infrastructure` and `ace.console` — folders exist in `src/`
  but have no projects yet; they are not required by the acceptance criterion (A/B
  scenario) of v0.1 and were not generated in this scope.
